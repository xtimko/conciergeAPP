# Контекст

При `sendPhoto` с полем `photo: https://...` файл забирают **серверы Telegram**. Если CDN недоступен им (гео, блокировки), Telegram возвращает ошибку — клиент видел сообщение без фото.

# Решение

В `telegramBotApi.js`: после неудачной отправки по URL сервер **скачивает** изображение (при необходимости через существующий `TELEGRAM_PROXY`) и повторяет `sendPhoto` как **multipart**.

Прокси-доставку превью во фронте (отдельный endpoint + `<img>`) не смешивать без отдельной проверки Mini App — прежняя попытка давала регрессии.

# Альтернативы

- Только публичный CDN «видимый из Telegram» — не всегда контролируемо с РФ-VPS.
- Загрузка файлов в своё хранилище и короткая ссылка — ок для данных заказа; отправка в Telegram всё равно может понадобиться multipart.
